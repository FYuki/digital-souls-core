## 実装と範囲

- `memory_retrieval.py`: `MemoryRetrieval` が `MemoryRecordStore` を受け、逐語の store/extractor へ依存せず検索する。query の事前認可、本文量制限、候補全体と結果の認可、15秒 embedding、各 await 後の再検証を維持する。
- `memory_record_store.py`: `RetrievalCandidate` と `retrievable` / `current` を追加。再検証には返した記録・Fact・link・Semantic 根拠を含む不変 snapshot を渡す。API の型・命名調整であり、監督設計からの機能上の逸脱はない。
- `postgres_record_retrieval.py` / `postgres_memory_records.py`: Episode・Semantic の現行 active 候補、有効な Fact/link、引用（reason を含む）と依存 Episode を batch で読む。履歴は unnest で指定した conversation/revision の組だけ取得する。Binding は完全一致。本文・版・状態・出典・依存の変化は `current` で拒否する。
- `memory_ranking.py`: 純関数 `rank_records` で候補20・閾値0.54・先頭基準の margin 0.002・同等帯内の言及日時（NULLS LAST）/作成日時/ID・最大5件を適用する。vector 検証は既存 helper を共有する。
- `memory.py` / `application.py`: 保存文・種別・部分日時・Fact・一時参照名の JSON と dispatch guard へ変更。逐語引用と保存 ID をモデルへ注入しない。記憶内の命令文はデータとして扱う。
- `MemoryService.search` と `MemoryStore` / `PostgresMemory` の search/candidates を撤去した。`MemoryService.extract/run/rebuild/_versions`、逐語の書込保存と `Memory` / `rank_memories`・評価ツールは #104 まで保持する。書込試験の `written` helper は job ID を取得して `results` port を読み、検索・部分文字列 fallback を再実装しない。
- [ADR 0022](../adr/0022-memory-retrieval-from-records.md) を Accepted とし、ADR 0009/0010/0011/0018 に置換注記だけを追加した。SPEC と docs/memory.md は未変更。
- push・PR 作成・merge は実施していない。監督がレビュー、品質ゲート再実行、PR 操作を担当する。

`evidence_version` は専用の使い捨て schema で該当 FK を一時除去して欠損参照を注入する防御試験である。
